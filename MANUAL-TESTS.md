# Physical keyboard acceptance checklist

> **Waived by the user on 2026-10-23 for the Beta 5 goal.** The 84 unchecked hands-on scenarios below are cancelled as completion gates. They were not performed and are not being reported as passed; keep this list as optional future QA guidance.

## KiWeave 1.0 additions

- [ ] Enable smooth scrolling and compare the Settings-page scroll feel on available 60/120/144 Hz displays; confirm speed is consistent, a long frame stall does not cause a jump, and turning smooth scrolling off returns to native scrolling.
- [ ] With **Allow network access** off, verify Check for updates refuses locally and a disposable HTTP mapping reports that network access is blocked without contacting the endpoint. Confirm ordinary remapping, profiles, layers, backups, and diagnostics still work.
- [ ] Toggle **Allow network access** and verify KiWeave stays responsive while the administrator prompt is active, settings controls cannot race the pending change, and declining restores the previous switch value; approve once and verify the new state persists after reopening Settings.
- [ ] Enable network access, repeat the update check, and trigger a disposable loopback-only HTTP action. Turn network access off again afterward unless it is wanted.
- [ ] With Discord connected, turn master network access off and verify local IPC mute/deafen still works without reconnect traffic; re-enable access and confirm reconnection resumes. Separately start Discord authorization, turn access off while waiting for the browser callback, and verify the local listener cancels; re-enable access and complete authorization normally.
- [ ] In both UI shells, start Discord authorization, close the connection dialog while the browser callback is pending, then return through the browser callback. Confirm KiWeave does not show a detached dialog, crash, or continue token exchange after cancellation.
- [ ] Start DDC monitor detection and the network-access administrator prompt separately, close KiWeave while each is pending, and confirm no delayed callback touches a closed window or causes a crash.
- [ ] Open Privacy Center and verify the listed storage sizes are plausible. Preview and export safe diagnostics, then inspect the file for mapping targets, custom profile names, commands, arguments, paths, URLs, request bodies, typed text, or key history; none should appear.
- [ ] Create a harmless log entry through a failed action, use **Clear local logs**, and verify mappings, profiles, preferences, and backups remain unchanged.
- [ ] Add a modifier layer using Caps Lock, map Layer F5 to Mute, save, then hold Caps Lock and press F5. Verify mute fires, neither Caps Lock nor F5 reaches the foreground app, and plain F5 still uses the base mapping after release.
- [ ] In a disposable setup with distinct Base/layer mappings, use **More → Reset function keys** and **Disable all function keys** while a modifier layer is selected. Confirm each operation affects only that layer, leaves Base and custom hotkeys untouched, and keeps the current editor section open; repeat from Custom hotkeys → PowerToys and confirm success/error feedback remains visible.
- [ ] While a layer key is held, disable shortcuts with the mouse and then release the layer key. Verify no stuck or unmatched key remains. Also press a second configured layer key while the first is held; the first layer should remain active and the second key should pass through normally.
- [ ] Export and re-import a configuration with two layers, then copy it into a named profile. Verify layer names, activation keys, and all mappings survive without activating or executing anything during import.
- [ ] Export/import a `.kiweavepack` containing a safe custom-hotkey action and profile. Review publisher/signature context, redacted comparison, base actions, and profile actions; cancel once, then import and confirm actions are staged only and the current shortcuts-enabled state is preserved. Verify command/script actions in both base and profile mappings are rejected, as are duplicate JSON fields or tampered signature sidecars.
- [ ] Open the bottom-left gear Settings page and verify startup, tray, automatic-profile, and update-check toggles persist immediately after reopening KiWeave. In a disposable legacy-data copy, confirm migration keeps `language.json` and its recovery backup without replacing a newer saved language. Choose Español, restart, and verify known static labels translate while unknown/dynamic labels and saved combo-box values remain intact; switch back to English and restart. Confirm mapping edits still require Save changes.
- [ ] Open **Integration health** and verify it reports live PowerToys, Discord, OBS/Spotify, monitor, audio-device, configuration, keyboard-layout, session, display, controller/MIDI, and enabled-extension state. Refresh and confirm checks rerun without freezing the UI or showing stale results; trigger repeated refreshes and verify only one device scan runs at a time; close KiWeave during a scan and verify no late-window error appears.
- [ ] Open Guide from Settings. Verify all 12 topic headings and readable scrolling, search by both a heading and body text, confirm an unmatched search shows “No matching topics.”, open Discord setup, and close with both Done and Escape.
- [ ] Resize the main window down to its minimum size and back up on both Function keys and Custom hotkeys. Verify the left list stays within its card and scrolls, the editor remains reachable, and custom-hotkey controls plus action buttons wrap instead of clipping horizontally.
- [ ] Hover each function-key row and custom-hotkey row. Verify custom rows show both shortcut and action summary, and the themed tooltip explains action maturity, dependencies, permissions, plus sequence/network safety where applicable.
- [ ] Turn launch update checks off, restart KiWeave, and confirm startup remains quiet; use Check for updates to verify the manual result appears without downloading anything.
- [ ] Create a `.kiweave` full backup, inspect its summary, restore it after a harmless temporary change, and verify the rollback folder was created. Confirm PowerToys settings were not changed. Also verify a legacy `.keyweave` backup still imports.
- [ ] Create two profiles, assign a different test application to each, hide KiWeave, and verify the active profile changes only when the matching app is foreground. With a non-Default profile active and its mappings different from Default, open Profiles → Add current and verify the new profile copies the active mappings, not Default.
- [ ] Add different private notes to the same function key and custom hotkey in two profiles, then switch between profiles and verify notes stay with their profile. Confirm existing Default-profile notes still appear and migrate when saved.
- [ ] In a disposable portable copy with a valid backup, corrupt `KiWeaveData\shortcut-suspension.txt` and launch the app. Verify a recovery warning and recovered process names; with both copies corrupt, verify remapping stays paused and both source files are preserved until you explicitly save a replacement list.
- [ ] Add a running app such as Discord to the application-specific shortcut suspension list. In both shells, verify custom chords unregister immediately when that app gains focus and restore when another app or the desktop takes focus; repeat rapid switches and test with the window hidden to tray. With unreadable suspension settings, verify shortcuts remain paused until the settings are recovered.
- [ ] In a safe fullscreen app, enable Game mode and test a configured F-key action, a Pass through F-key, an Unbound F-key, and a standalone custom key. Configured actions should remain KiWeave-controlled, Pass through should reach the app, Unbound should suppress the key, and custom bindings should still work. Disable Game mode afterward.
- [ ] In a disposable user-data copy, damage the private mapping-notes file and reopen KiWeave. Verify a valid `.bak` is used without altering the damaged file; if both are unreadable, note saving must be refused and both files left untouched.
- [ ] Confirm automatic switching pauses while the editor is visible and while it has unsaved changes. In a disposable data copy, schedule a profile to start at the next minute boundary and verify both WinForms and WPF activate it within 30 seconds; pin another profile and verify the scheduled switch is suppressed.
- [ ] Switch profiles from the tray and verify the selected function-key and custom-hotkey mappings become active. If a modifier layer was being edited, verify the editor returns to Base instead of silently selecting the same layer index in the new profile, while the selected F-key stays selected; if activation fails, verify the previous layer and visible mapping list are restored. With a profile pinned, rename it in the profile manager and verify the pin follows the renamed profile; choose another profile through **Use profile** while pinned and verify the pin follows that selection. From an automatically matched profile, use **Use profile** to select another and verify its automatic status clears. Delete a pinned profile and verify its stale pin clears.
- [ ] Click the active-profile badge and verify the explanation matches a manual selection or foreground-app rule. Pin the profile, foreground a differently matched app, and verify the pinned profile remains active; resume automatic switching and verify matching resumes after KiWeave is hidden.
- [ ] Assign **Activate and pin profile** to a harmless F-key or custom hotkey. Trigger it and verify the selected profile becomes active and remains pinned only until resume or app exit.
- [ ] In a disposable setup, create a profile and map a function key, a layer key, and a custom-hotkey sequence/conditional to **Activate profile** for it. Remove that profile from the WPF Profiles page, choose to remap saved references, and verify every action now targets Default; if the removed profile was active, verify Default becomes active too. Repeat and cancel the remap prompt once; all profile files and actions must remain unchanged.
- [ ] Create a profile inheriting from Default and override only F2. Change Default F1, reopen the inherited profile, and verify F1 follows Default while F2 keeps its override. Verify an inheritance loop is refused.
- [ ] Open **Settings → Live key tester**, press a physical F key and an ordinary typing key, and verify only the latest event is shown with modifiers, source, decision, profile/layer, and resolved action. Close/reopen it and verify no prior event or key history remains.
- [ ] Open **Settings → Conflict center** with a harmless duplicate shortcut or profile rule. Verify the result explains what wins, exposes no action target/path/URL, and **Open relevant area** navigates without changing or executing anything.
- [ ] In **Custom hotkeys → PowerToys**, verify it stays in the same page instead of opening a popup. Check active shortcut selection/editing, Add shortcut with an off or unassigned function, module enabling, Save/Cancel, Refresh, and Open PowerToys Settings. Confirm the saved shortcut is backed up and the active list refreshes; do not test on a shortcut you rely on.
- [ ] Choose **Record** beside a custom-hotkey shortcut, physically press Ctrl+Alt+K, release it, and verify the dialog shows exactly `Ctrl+Alt+K` without activating another app. Accept it, then repeat for a Send key/Send shortcut action field. Verify a plain letter is rejected for the global hotkey, Ctrl+Alt+Delete is rejected, Ctrl+F12 reports Windows' debugger reservation without disabling other custom bindings, Escape cancels, and reopening the recorder shows no prior key. Assign **Pass through normally** to a modifier chord and verify the target app still receives it; change to **Unbound** and verify the chord is consumed without an action.
- [ ] Select an existing custom hotkey and edit its **Shortcut** field or use its **Record** button. Save, then verify the row, editor heading, and active binding use the normalized new chord and the old chord no longer triggers. Try changing it to another row's chord and verify the save is rejected without changing the active configuration. For a modifier+F-key chord that Windows cannot register, verify the saved base mapping for that F key still works; when a temporary conflict is cleared, verify KiWeave retries the custom chord within about a second without another save. Also bind Ctrl+F1 and test both Ctrl+F1 and Ctrl+Shift+F1, confirming only the exact matching chord wins and no duplicate action fires. Repeat in a non-default profile and confirm the edit persists after switching away and back.
- [ ] Add a custom hotkey, choose **Record**, and press each available dedicated volume/playback button without modifiers. Verify the exact media name is captured. Assign one to a harmless custom action, save and enable it, then verify both press and release are suppressed and the original media action does not leak through. Also verify **Pass through normally** preserves a media button and **Unbound** consumes it. Holding Volume up/down should repeat only when its assigned action supports repeat. If an Eject key is available, verify one physical press queues exactly one mapped action; if two consumer-control Eject devices are available, verify both can trigger the mapping and unplug/reconnect one to confirm its first press still works. Restore normal media behavior afterward by removing the test mapping.
- [ ] Save a harmless mapping change, open **Settings → Undo and history**, and verify a new local snapshot describes the changed key without showing its target/path/URL. Restore it, confirm the setup returns to the earlier value, and verify the pre-restore state was itself preserved as a newer history entry. Do not use a destructive action for this test.
- [ ] Use Diagnostics and verify its copied report contains no action targets, command arguments, URLs, or personal paths.
- [ ] Use Toast debug and trigger real remapped actions: verify the toast fades in, remains visible for about 1.5 seconds, and fades out; repeat actions quickly to check that overlapping updates neither crash KiWeave nor leave a stuck toast. With media active, verify the compact card shows the song title, album art, and correct Playing/Paused state; with album art unavailable, verify it falls back to the known player app icon (Spotify branding for Spotify, browser app icon for Chrome) without guessing a website; verify no media toast appears when there is no active media session or when the player app itself is foreground.
- [ ] Test **Switch to next audio output** with at least two active playback devices, then restore the preferred default device.
- [ ] Test center-window and always-on-top against ordinary, non-elevated windows.
- [ ] Test Discord, Spotify, OBS, and PowerToys actions only after reviewing the relevant app's own shortcut/settings state. For Spotify, bind custom chords to Play/Pause, Next, and Previous; verify each changes the active player once without the chord leaking to the foreground app. Disable the Spotify extension and confirm these custom bindings report the disabled state without issuing media commands, then restore its prior setting.
- [ ] With a connected XInput controller, add a harmless Controller 1 button trigger and verify the matching rising press invokes only the selected saved function-row action; verify release/re-press behavior and that Controller 2–4 map to their own devices. If a MIDI input is available, test NoteOn and ControlChange triggers by device/channel/value. Disable the Controller/MIDI extension and verify triggers pause, then re-enable it; confirm no raw controller or MIDI history is stored.
- [ ] Verify controller triggers poll at the active display's refresh cadence: test on the normal display and, if available, a higher-refresh display; move the foreground window between displays and confirm cadence follows within about one second. Confirm disabling Controller/MIDI stops polling and re-enabling it resumes only when mappings exist.
- [ ] In Extensions, toggle an extension and verify its card immediately moves between **Installed extensions** and **Featured first-party extensions**. Enable the Stream Deck extension and verify its plugin reports ready, **Show settings** opens KiWeave to Settings, and **Activate profile** uses the normal unsaved-edit guard and pins the selected profile. With tray mode on, close KiWeave to tray and verify Stream Deck remains connected; cancel an unsaved Exit and verify it remains connected then too. - [ ] Point an HTTP action at a disposable local endpoint and verify GET/JSON POST behavior and the eight-second timeout. Do not use secrets in exported configurations.
- [ ] Build a conditional action on a harmless F key: **Foreground application is Notepad.exe**, matching action **Mute / unmute**, fallback **Do nothing**. Save, focus Notepad, press the key, then focus another app and press it again. Verify only the matching press mutes.

Keep settings visible during the first test. Start with remapping off. Save mappings before enabling them. These checks require the user's actual keyboard and applications; they are not claimed as completed by synthetic-input tests.

- [ ] **F5 volume and suppression:** Map F5 to Media / Volume up and Save. Open a harmless browser page; turn remapping on, then physically press F5. Verify volume rises and the page does not refresh. Hold F5 briefly to verify repeat. Restore the desired volume afterward. If necessary compare F5 and Fn+F5 on the Apple/Boot Camp keyboard.
- [ ] **Plain key:** Map F4 to Send a key / A. In a blank unsaved Notepad document, press F4 once and hold it briefly. Exactly one A should appear for each separate press. No F4 behavior should leak through.
- [ ] **Shortcut:** Map F6 to Ctrl+Shift+S. In a harmless blank document, verify one Save As dialog opens per press; cancel it. Try Alt+Tab if desired. Confirm modifier keys still behave normally afterward.
- [ ] **No recursion:** Map F4 to F5 and F5 to Volume up. Press F4 once. It should emit a normal F5, not activate the F5 mapping. Choose a harmless foreground application for this check.
- [ ] **Application launch:** Map F7 to the Notepad executable using the file picker. Press and hold F7. Only one launch should occur. Release and press again to verify a second launch.
- [ ] **File/folder/shortcut:** In turn, map F8 to a harmless .txt file, a local folder, and a .lnk pointing to Notepad. Verify the expected associated app, Explorer folder, and shortcut open. Close test windows afterward.
- [ ] **Command/script:** Choose a harmless existing test script or command and verify its expected local result. Try arguments containing spaces and a working directory. Do not test commands you do not understand.
- [ ] **Unbound:** Map F5 to Unbound. Press it in a browser; nothing should happen.
- [ ] **Pass through:** Map F5 to Pass through. Its normal refresh behavior should return.
- [ ] **Global off:** With F5 mapped to a media action, turn remapping off in the window, then test again using the tray toggle. F5 should behave normally.
- [ ] **Emergency off:** Enable a mapping, hold Ctrl+Alt+Shift together for at least 1.5 seconds, and release. Confirm the status changes to off and new F-key presses pass through. Repeat once with right-side modifiers. It should never toggle on by itself.
- [ ] **Mid-press transitions:** Hold a mapped key, turn remapping off with the mouse, then release the key. New presses should pass normally. No modifier or destination key should remain stuck.
- [ ] **Exit:** Enable a mapping, exit the app, and verify immediate restoration of normal keys. Reopen it to continue.
- [ ] **Persistence:** Save several mappings, exit, and reopen. Verify the mappings and enabled preference are restored.
- [ ] **Export/import:** Export, change the editor, then import the exported file. Verify all twelve entries match. Changes should become active only after Save; import should not turn remapping on.
- [ ] **Invalid import:** Import a copy with invalid JSON, a duplicate key, an unknown field, an invalid shortcut, or a non-local target. Verify an error and no replacement of valid live/editor configuration.
- [ ] **Missing target:** Save a mapping to a disposable test file, then move that file. Trigger the mapping and verify a visible warning with no crash.
- [ ] **Tray and close:** With Keep running in tray on, close the window and reopen it from the blue F icon or Search. Remapping should keep running. On first opening the tray menu and after profile/state changes, verify its toggle and active-profile labels match the real state. With tray use off, closing must exit. The Exit button must quit in either mode.
- [ ] **Startup (optional):** Only if desired, tick Start with Windows in Settings. Sign out/in and verify tray startup. Untick it afterward if not wanted.
- [ ] **Elevated app limitation:** Compare a standard and elevated harmless app, if needed. Record limitations without changing Windows security settings.

The source audit and automated tests verify that the program does not write pressed keys to logs. Optional additional inspection: the live setup should be saved as `config.kiweave`; exported configs, backups, recovery drafts, and history snapshots use `.kiweave`. Internal preferences and profile stores may remain JSON and are not user-exported setup files.
